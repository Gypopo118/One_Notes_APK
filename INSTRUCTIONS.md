# Рефакторинг будильника — инструкция по замене

## Что изменилось и почему (кратко)

| Проблема | Причина | Исправление |
|---|---|---|
| Нет полноценного будильника при выключенном экране | Использовался только `@capacitor/local-notifications`, без AlarmManager/foreground-сервиса | Добавлен нативный слой: `AlarmReceiver` → `AlarmService` (foreground, `setAlarmClock`) → `AlarmActivity` |
| «Звук отключён» в настройках канала | `NotificationChannel` иммутабелен после создания; старые ID канала с дефолтным/пустым звуком остались у пользователей | `AlarmService.deleteStaleChannels()` удаляет все прежние ID, создаётся новый `alarm_channel_v6` с явными `AudioAttributes(USAGE_ALARM)` |
| Путь к звуку битый / выбор мелодии не работает | Ссылка вела на несуществующий/недоступный ресурс, не было persistable-доступа к выбранному файлу | Приоритет: пользовательский файл (SAF + `takePersistableUriPermission`) → системный `RingtoneManager.TYPE_ALARM` (гарантированно существует) → `Ringtone.play()` как последний рубеж |
| Нативные правки исчезали при пересборке | `android/` не в репозитории, генерируется заново `cap add android` при каждом CI-запуске | Новый шаг `scripts/patch-android.py` в `build-apk.yml`, копирующий `android-native/` и патчащий манифест при каждой сборке |

## Куда положить файлы (структура репозитория)

```
<репозиторий>/
├── android-native/                  ← НОВОЕ, скопировать целиком
│   └── app/src/main/
│       ├── java/com/mynotes/app/
│       │   ├── MainActivity.java
│       │   └── alarm/
│       │       ├── AlarmScheduler.java
│       │       ├── AlarmReceiver.java
│       │       ├── AlarmService.java
│       │       ├── AlarmActivity.java
│       │       ├── BootReceiver.java
│       │       └── NativeAlarmPlugin.java
│       └── res/
│           ├── layout/activity_alarm.xml
│           └── drawable/ic_stat_alarm.xml
├── scripts/
│   └── patch-android.py             ← НОВОЕ
├── js/
│   └── reminders.js                 ← ЗАМЕНИТЬ существующий
└── build-apk.yml                    ← ЗАМЕНИТЬ существующий (в .github/workflows/)
```

`package.json` уже содержит `@capacitor/local-notifications` — его можно **оставить** (используется как fallback вне Android), удалять не нужно.

## Шаги

1. **Скопировать `android-native/`** целиком в корень репозитория рядом с `package.json`.
2. **Добавить `scripts/patch-android.py`** — сделать исполняемым (`chmod +x`) не обязательно, вызывается через `python3`.
3. **Заменить `.github/workflows/build-apk.yml`** на приложенный — ключевое отличие: новый шаг *"Patch native alarm sources into generated Android project"* идёт **после** `cap add android` и **до** `cap sync`.
4. **Заменить `js/reminders.js`**.
5. В `app.js`, в `init()`, после `Reminders.rearm(...)` добавить (не обязательно, но настоятельно рекомендуется — без этого на Android 12+/MIUI разрешения на точные будильники и полноэкранный интент не будут запрошены сами):
   ```js
   try { await Reminders.ensureAlarmSetup(); } catch (e) {}
   ```
   Лучше вызывать это не при каждом запуске, а один раз при создании первого напоминания с сроком — так пользователь увидит системные диалоги в осмысленный момент, а не сразу при открытии приложения.
6. Закоммитить и запустить workflow (push в `main`/`master` или `workflow_dispatch`).

## Что дополнительно стоит сделать в UI (не входит в код выше)

- Кнопка «Выбрать мелодию» в настройках → `await Reminders.pickCustomSound()`.
- Если `Reminders.ensureAlarmSetup()` не вызывается автоматически — дать пользователю ручную кнопку «Проверить разрешения будильника» на экране настроек, особенно важно для HyperOS/MIUI, где системный диалог игнора батарейной оптимизации нужно подтверждать явно.

## Известные ограничения (честно, как в вашем плане — этап 4)

- Автозапуск в списке разрешений MIUI/HyperOS и другие OEM-специфичные white-list'ы кодом не закрываются — только `requestIgnoreBatteryOptimizations()` как частичная мера. Для полного решения на агрессивных прошивках нужно вести пользователя в соответствующий раздел настроек производителя (кнопка в UI с инструкцией — отдельная небольшая задача).
- `setAlarmClock()` показывает постоянную иконку будильника в статус-баре, пока алярм запланирован — это ожидаемое системное поведение (так Android отличает «настоящие» будильники и даёт им максимальный приоритет), не баг.
- Код не компилировался и не тестировался на устройстве в этой сессии (нет Android SDK в текущем окружении) — после интеграции обязательно проверьте сборку локально/в CI и реальное срабатывание на заблокированном экране и после перезагрузки устройства.
